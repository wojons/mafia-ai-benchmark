The repo's own driver is `scripts/release.sh` (no Makefile, no goreleaser, no
changesets, no npm publish — the manifest is `private: true`). Its gates, in
order: clean tree (`-- . ':!.gitreins' ':!.coding-hermes'`), `origin/main..main`
count 0, 5 manifests agree, target tag absent locally **and** on origin,
`CHANGELOG.md` carries `## [$V]`, no `{{INSTALL_DATE}}` token, `gh run list
--branch main` newest run `headSha == HEAD` and `conclusion == success`,
`pnpm audit --prod` clean, `pnpm build` of shared/server/cli produces
`apps/server/dist/index.js`.

Two-commit sequence (forced by the empty `[Unreleased]`, which is the normal
state of this repo — contributors do not populate it):

1. **Notes commit.** Write the `[Unreleased]` body: one entry per material
   commit (§4), scope + what changed + backticked short SHA, plus a
   "Carried forward" subsection for §8. Touch `CHANGELOG.md` only. Push, wait
   for exact-SHA CI green.
2. **Promotion commit.** Promote `[Unreleased]` → `## [1.3.0] — <date>` and
   re-open an empty `[Unreleased]`; bump the 5 manifests + `VERSION` to
   `1.3.0`. Rollover diff must be small and explicit (`git diff --numstat`) —
   more than the heading rollover means the driver rewrote too much.
   Push, wait for exact-SHA CI green. **This SHA is the tag target.**
3. `scripts/release.sh auto` from a clean tree at that SHA — or hand-run the
   gates and tag by SHA. Verify after: `gh release view v1.3.0`, and the
   tag-triggered CI run (`on: push: tags: ['v*']`) green.

Do not tag the moving tip: board lanes push every few minutes, and the driver's
`HEAD == origin/main` precondition fails the moment one lands. Re-anchor forward
to the new tip, never reset.
